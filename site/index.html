🛡 MCP server for WHMCS · MIT licensed

Give an agent your WHMCS instance — without giving it the keys to billing.

whmcs-mcp exposes the WHMCS External API as typed MCP tools: read-only by default, write actions opt-in per domain, billing and destructive mutations gated behind a two-step confirmation, and PII/secrets redacted before anything reaches the model.

Why this exists

WHMCS runs live billing. An MCP server that lets an agent touch it has to default to safe, make unsafe actions visible before they happen, and never leak what it reads. Nine other WHMCS MCP servers exist; none combine an open MIT license, TypeScript, a tiered safety model, confirmation-gated mutations, and redaction by default. See the full comparison.

🔒 Read-only by default

Every install starts in readonly mode. Write, billing, and destructive tools aren't just refused — they aren't advertised to the model at all.

🧾 Confirmation-gated mutations

Billing and destructive tools return a preview and a short-lived, single-use confirmToken. The mutation only runs when that token is echoed back.

🕶 Redaction, always on

Card and bank data, passwords, CVVs, EPP codes, and (optionally) email/phone are stripped from every response and every error message before the model sees them.

🧬 Version-aware

Calls WhmcsDetails at startup and exposes it as a resource, so an agent — and you — always know which WHMCS core it's actually talking to.

🧪 Dry-run everywhere

Every mutating tool accepts dryRun: it builds and validates the WHMCS request without ever sending it.

📖 Typed, documented, generated

Every tool has a zod schema mirroring WHMCS's own parameter tables, and the docs on this page are generated straight from that schema — not written by hand and left to drift.

The safety model

Every tool declares a tier. The tier decides whether it's advertised at all, and whether it needs a confirmation round-trip before it can touch anything.

TierAdvertised whenConfirm gateExample
read Always (any mode) — tickets_list, billing_get_invoice
write WHMCS_MCP_MODE=write or full Destructive-flavored writes only (e.g. merges) tickets_reply, clients_update
billing WHMCS_MCP_MODE=full only Always — preview + confirmToken billing_add_payment, orders_create
destructive WHMCS_MCP_MODE=full only Always — preview + confirmToken tickets_delete, orders_cancel
1

Mode gates advertisement

WHMCS_MCP_MODE (readonly / write / full) plus WHMCS_MCP_ENABLE_DOMAINS decide which tools the model even sees in its tool list.

2

First call returns a preview

Calling a billing or destructive tool without a token returns what would happen and a single-use confirmToken, bound to that tool and those exact arguments.

3

Second call must echo the token

The token expires after 5 minutes and can only be spent once. Argument drift between the preview and the confirm call invalidates it.

4

Response is redacted, then returned

Every result — success or WhmcsApiError — passes through src/safety/redact.ts before it reaches the model or a log line.

Operator policy note: invoice-mutating tools (billing_create_invoice, billing_update_invoice, billing_add_payment, billing_apply_credit, billing_capture_payment) live in the billing tier by design — off unless the operator explicitly sets WHMCS_MCP_MODE=full. See SECURITY.md for the least-privilege WHMCS API role recipe.

Install

Works over stdio with any MCP client. Pick your client below.

// claude_desktop_config.json
{
  "mcpServers": {
    "whmcs": {
      "command": "npx",
      "args": ["-y", "@peguesj/whmcs-mcp"],
      "env": {
        "WHMCS_API_URL": "https://billing.example.com/includes/api.php",
        "WHMCS_API_IDENTIFIER": "<identifier>",
        "WHMCS_API_SECRET": "<secret>",
        "WHMCS_MCP_MODE": "readonly"
      }
    }
  }
}
claude mcp add whmcs -- npx -y @peguesj/whmcs-mcp \
  --env WHMCS_API_URL=https://billing.example.com/includes/api.php \
  --env WHMCS_API_IDENTIFIER=<identifier> \
  --env WHMCS_API_SECRET=<secret> \
  --env WHMCS_MCP_MODE=readonly
// .cursor/mcp.json
{
  "mcpServers": {
    "whmcs": {
      "command": "npx",
      "args": ["-y", "@peguesj/whmcs-mcp"],
      "env": {
        "WHMCS_API_URL": "https://billing.example.com/includes/api.php",
        "WHMCS_API_IDENTIFIER": "<identifier>",
        "WHMCS_API_SECRET": "<secret>",
        "WHMCS_MCP_MODE": "readonly"
      }
    }
  }
}
# global install
npm install -g @peguesj/whmcs-mcp

# run over stdio (default)
WHMCS_API_URL=https://billing.example.com/includes/api.php \
WHMCS_API_IDENTIFIER=<identifier> \
WHMCS_API_SECRET=<secret> \
whmcs-mcp

# or Streamable HTTP, bound to localhost only
whmcs-mcp --http --port 4180

Full configuration reference, including WHMCS_MCP_ENABLE_DOMAINS, redaction toggles, and rate limiting: see docs/configuration.md.

How this compares

A short field guide to the existing WHMCS MCP servers, and what each one is worth borrowing from.

ProjectLicenseLanguageNotable
whmcs-mcp (this repo) MIT TypeScript Read-only default, tiered safety, confirm-gated billing/destructive tools, redaction by default, runtime version detection
toc-whmcs-mcp AGPL-3.0 Go Closest in spirit — read-only default, confirmation-gated mutations, redacted output; reaches all 162 documented actions via profiles
daddariotech/whmcs-mcp Commercial TypeScript 98 tools, dryRun everywhere, documents minimum API-role permissions per tool; paid license key
caioldcarvalho/whmcs-mcp MIT TypeScript 34 tools, npm trusted publishing, no tiered safety model — holds the unscoped whmcs-mcp npm name
whmcs-mcp-server ISC TypeScript 60+ tools across clients/tickets/products/invoices/orders/domains — holds the whmcs-mcp-server npm name
whmcs-mcp-tool MIT — Most-starred; CI, a GHCR Docker image, and a generated API reference doc

The unscoped npm names whmcs-mcp and whmcs-mcp-server are already taken by the two projects above, which is why this package publishes as @peguesj/whmcs-mcp.
